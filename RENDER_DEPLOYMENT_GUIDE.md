# Deploying Your Blood Donation Platform on Render

This guide will walk you through deploying your Django blood donation platform on Render.com.

## Prerequisites

1. A free Render account at [https://render.com](https://render.com)
2. Your project hosted on GitHub, GitLab, or Bitbucket
3. Updated code with the deployment files provided in this repository

## Steps to Deploy

### 1. Prepare Your Repository
- Ensure all the files in this repository are committed to your Git repository
- Make sure the following files are present:
  - `Procfile` - tells Render how to run your app
  - `runtime.txt` - specifies Python version
  - Updated `requirements.txt` with `dj-database-url`
  - Updated `settings.py` with Render compatibility
  - `deploy.sh` - deployment script

### 2. Create a New Web Service on Render
1. Log in to your Render dashboard
2. Click "New +" and select "Web Service"
3. Connect your GitHub/GitLab/Bitbucket account
4. Select your blood donation project repository
5. Select the branch you want to deploy (typically `main` or `master`)

### 3. Configure the Web Service

#### Environment Variables
Add the following environment variables:

- `DEBUG`: Set to `False` (or leave empty)
- `SECRET_KEY`: Generate a strong secret key (you can use Python's secrets module: `python -c 'import secrets; print(secrets.token_urlsafe(50))'`)
- `DATABASE_URL`: This will be automatically provided by Render's PostgreSQL add-on
- `REDIS_URL`: This will be automatically provided by Render's Redis add-on (optional, for advanced features)
- `EMAIL_HOST_USER`: Your email address for sending emails
- `EMAIL_HOST_PASSWORD`: Your email password or app-specific password
- `EMAIL_BACKEND`: Set to `django.core.mail.backends.smtp.EmailBackend` (or leave empty to use default)

#### Build & Start Commands
- **Build Command**: `pip install -r requirements.txt && python manage.py collectstatic --noinput`
- **Start Command**: `gunicorn blood_donation.wsgi:application`

#### Environment
- **Environment**: Python
- **Runtime**: Will be detected from your `runtime.txt` file

### 4. Add-ons (Optional but Recommended)

#### PostgreSQL Database
1. In your service dashboard, go to "Add-ons"
2. Select "PostgreSQL" 
3. Choose the free tier plan
4. Connect it to your web service
5. The `DATABASE_URL` environment variable will be automatically added

#### Redis (for Celery and caching)
1. In your service dashboard, go to "Add-ons"
2. Select "Redis" 
3. Choose the free tier plan
4. Connect it to your web service
5. The `REDIS_URL` environment variable will be automatically added

### 5. Manual Database Migration

Since Render doesn't run custom post-deploy scripts by default, you'll need to manually run migrations after the first deployment:

1. After your initial deployment completes, go to your service dashboard
2. Click on "Manual Deploys" 
3. Click "Runbook" or "SSH" if available
4. Or use the Render CLI to connect to your instance and run:
   ```bash
   python manage.py migrate
   ```
   
Alternatively, you can create an initial user via Django shell after deployment:
```bash
python manage.py shell
```
Then in the Python shell:
```python
from accounts.models import User  # Adjust according to your User model location
User.objects.create_superuser('admin', 'admin@example.com', 'your_secure_password')
```

### 6. Domain Configuration (Optional)

1. In your service dashboard, go to "Domains"
2. Add your custom domain or use the default render.com subdomain
3. Follow Render's instructions for DNS configuration

## Environment Variables Reference

| Variable | Description | Example |
|----------|-------------|---------|
| `DEBUG` | Django debug mode | `False` |
| `SECRET_KEY` | Django secret key | `a_very_long_random_string` |
| `DATABASE_URL` | Database connection string | Auto-generated by Render PostgreSQL |
| `REDIS_URL` | Redis connection string | Auto-generated by Render Redis |
| `EMAIL_HOST_USER` | SMTP username | `you@example.com` |
| `EMAIL_HOST_PASSWORD` | SMTP password | `your_app_password` |

## Troubleshooting

### Common Issues

1. **Database Error**: Make sure PostgreSQL add-on is connected and migrations have run
2. **Static Files Not Loading**: Ensure `collectstatic` ran during build process
3. **Environment Variables Missing**: Double-check all required variables are set
4. **SSL/Security Errors**: The provided settings handle most security concerns for Render

### Checking Logs
- View your service logs in the Render dashboard under your web service
- Look for any error messages during the build or runtime phases

## Post-Deployment

After successful deployment:
1. Visit your site's URL
2. Navigate to `/admin/` to access the Django admin
3. Test user registration and login functionality
4. Verify that all features are working as expected

## Updating Your Deployment

To update your deployed application:
1. Make changes to your code locally
2. Commit and push changes to your connected Git branch
3. Render will automatically detect the changes and deploy a new version
4. Monitor the deployment logs to ensure everything works correctly

## Scaling Considerations

As your blood donation platform grows:
- Consider upgrading to paid plans for increased resources
- Add load balancing if needed
- Implement proper monitoring and alerting
- Set up backup strategies for your database
